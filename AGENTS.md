# Project continuity instructions

Before making product, architecture, trading-safety, data, or workflow decisions:

1. Read `DECISION_LOG.md` and `ARCHITECTURE.md`.
2. Treat `ARCHITECTURE.md` as the authoritative architecture source and Mermaid definition.
3. Update `ARCHITECTURE.md` when component responsibilities, boundaries, status, priority, integrations, or material data flows change.
4. Update `DECISION_LOG.md` when a material decision is confirmed, revised, or superseded.
5. Keep the version and change history current in both documents.
6. Do not describe an unimplemented component as complete.
